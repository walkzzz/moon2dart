# moon2dart 编码规范 | Coding Conventions

> v0.10.0 · 2026-11-16 · 含语义等价标注规范 + --strict 模式

## 1. MoonBit 源码规范 | MoonBit Source Conventions

### 1.1 文件组织 | File Organization
- 每个包一个目录，含 `moon.pkg`
- 源文件用 `.mbt`，测试文件用 `_test.mbt`（blackbox）/ `_wbtest.mbt`（whitebox）
- **注意**：源文件名不能含 `_test`（会被视为测试文件）

### 1.2 代码风格 | Code Style
- 块风格：每个定义以 `///|` 分隔
- `pub fn` 必须有 `///` 文档注释
- 方法定义：`fn Type::meth(self : Type, ..)`
- 布尔取反：`!expr`（非 `not(x)`）
- range：`0..<n`（排他）/ `0..=n`（包含）
- 字符串插值：`\{expr}`

### 1.3 trait 使用 | Trait Usage
- 跨包实现用 `pub(open) trait`
- impl：`pub impl Trait for Type with method` + `pub extend Type with Trait::{method}`
- derive：`derive(Debug, Eq)` + `pub extend Type with Trait::{method}`

### 1.4 命名 | Naming
- 类型：PascalCase（`MoonType`、`DartEmitter`）
- 函数/变量：snake_case（`emit_dart`、`map_type`）
- 常量：UPPER_SNAKE（`DEFAULT_INDENT`）
- 包：snake_case（`typesys`、`codegen`）

## 2. 生成 Dart 代码规范 | Generated Dart Code Conventions

### 2.1 风格 | Style
- 遵循 `dart format` 默认风格
- 缩进 2 空格
- 行宽 80 字符
- 生成可读代码（非压缩），便于人工审查

### 2.2 结构 | Structure
```dart
// 文件头：自动生成标记
// Generated by moon2dart
// Source: input.mbt
// DO NOT EDIT BY HAND

// 1. imports
import 'dart:typed_data';

// 2. 自定义类型（如 Result）
class Result<T> { ... }

// 3. 类型声明（struct → class）
class Point { ... }

// 4. enum → sealed class
sealed class Color { ... }

// 5. 函数
int add(int a, int b) { ... }
```

### 2.3 命名保持 | Name Preservation
- MoonBit 标识符原样保留（MoonBit 和 Dart 命名规则兼容）
- 关键字冲突时加 `$` 前缀（如 MoonBit `class` → Dart `$class`）

## 3. 语义等价标注规范 | Semantic Equivalence Annotation Conventions

### 3.1 语义等级分类标注

生成 Dart 代码时，L3/L4 类型自动添加诊断注释：

```dart
// L3 受限等价 — 自动生成
// [L3-CONSTRAINED] UInt: unsigned semantics lost, mapped to signed int
int x = 42;

// L3 受限等价 — Float 精度提升
// [L3-CONSTRAINED] Float: 32-bit float promoted to 64-bit double
double y = 1.0;
```

### 3.2 strict 模式

CLI `--strict` 选项启用严格模式：
- L4 类型直接 raise `Moon2DartError::TypeError`，不生成代码
- L3 类型允许生成但添加诊断注释
- 用法：`moon2dart convert <file> --strict`

### 3.3 嵌套 Option 处理约定

检测到嵌套 Option 时：
1. 自动生成 `Option<T>` 辅助类（some/none 工厂 + isSome/isNone 属性）
2. 类型映射使用 `DNullable(DNullable(inner))` 表示嵌套
3. 不允许直接映射为 `T??`（Dart 会塌缩）

```dart
// ✅ 正确：辅助类保留三分态
Option<Option<int>> config = Option.some(Option.some(42));

// ❌ 错误：int?? 塌缩为 int?，丢失 Some(None) 状态
int?? config = 42;
```

## 4. 测试规范 | Testing Conventions

### 4.1 测试文件 | Test Files
- blackbox：`xxx_test.mbt`（测试公开 API）
- whitebox：`xxx_wbtest.mbt`（测试内部）
- 每个 pub fn 至少一个测试

### 4.2 断言 | Assertions
- 优先 `assert_eq`
- 类型映射测试：`assert_eq(map_type(MInt), DInt)`
- codegen 测试：`assert_eq(emit_dart_type(DInt), "int")`
- 快照测试：复杂输出用 `debug_inspect` + snapshot

## 5. 验收门禁 | Acceptance Gate

```bash
moon check          # 0 warning 0 error
moon test           # 全通过
moon fmt            # 格式化
moon info           # API 变更检查
```

每次提交前必须通过四项门禁。

## 6. 提交规范 | Commit Conventions

- 单一 commit per 迭代
- 格式：`vX.Y.Z: <摘要> — <变更点>`
- 示例：`v0.1.0: transpiler 骨架 — 类型映射 + AST + codegen + CLI`
